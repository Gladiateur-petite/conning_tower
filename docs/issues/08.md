# Battle Parserを純粋化し最終HPを一括反映する

計画ID：08（GitHub番号ではない）
推奨branch：`refactor/battle-atomic`
依存計画ID：07

## Background

現行は可変ShipとhashCodeのdamage mapを使い途中失敗が状態へ影響し得る。

## Requirement

initial snapshotからSuccess/Failureを返すparser境界、明示的side/index/instance ID、atomic反映を実装する。

## Acceptance Criteria

- [ ] 対応形式の全艦HP一致。途中例外・配列不整合は実状態を部分更新せずUNKNOWNへ。
- [ ] diff reviewとPRに根拠・検証結果・未対応を記録する。

## Safety considerations

releaseでも動く入力検証を使う。assertだけに依存せず、未知フェーズを無視しない。

## Test cases

通常/連合/短編成/7隻/端数/過剰damage/途中例外/重複。期待値は人間検算。

人間レビュー：仕様解釈と期待値、変更対象、失敗時の扱い、実行結果を確認する。
