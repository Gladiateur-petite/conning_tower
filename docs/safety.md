# 大破警告とHP信頼性の方針

これは採用予定の設計であり、現行ConningTowerで保証される挙動ではない。ゲームへは介入しない。

## 状態

| 状態 | 条件 | 表示 |
|---|---|---|
| SAFE | 現在の出撃/戦闘世代の全対象艦HPが検証済み、確定退避艦を除き大破なし | 「大破検出なし（取得済みHP）」と情報の時点 |
| DANGER | 有効なHPで少なくとも1艦がHP×4 <= MaxHP | 艦名・HP/MaxHP・大破。持続表示 |
| UNKNOWN | 未取得、欠落、不正データ、未対応戦闘、取得機構停止、世代不一致等 | 「HP判定不能」・理由・最終正常取得時点 |

判定前提はMaxHP>0、0<=HP<=MaxHP、艦ID/艦隊位置一致。有効HP=0はDANGER。未知のHP=0への置換はしない。

複数艦を集計するとき、有効な大破艦があればDANGERを維持し、他に不明艦があれば同時に「判定不能艦あり」を表示する。大破が既知でなければUNKNOWNがSAFEに優先する。欠落時に以前の大破情報を消さず「前回大破、現在HP不明」と保持する。赤い既知情報と不明理由を二者択一にしない。

## 遷移と解除

| 事象 | 次の扱い |
|---|---|
| 起動/キャッシュ読込/途中出撃からListener開始 | UNKNOWN。cacheは最終値として閲覧可能、SAFEの根拠にしない |
| 出撃開始 | 対象艦隊/出撃IDを確定。母港snapshotとの連続性を検証。不足はUNKNOWN |
| 戦闘開始・関連API取得待ち | 判定を保留してUNKNOWN表示。直前大破の表示も保持 |
| 対応戦闘の完全解析成功 | 全対象艦の結果をatomicに反映し再判定 |
| エラー/タイムアウト/未対応/途中例外 | 関係するHPを失効。古い正常HPを流用せずUNKNOWN |
| map/nextを観測したのに前戦闘結果が欠ける | シーケンス欠落としてUNKNOWN |
| 再送/重複 | 出撃IDと内部event IDで処理済みを判定。二重減算しない |
| ログ設定OFF | 保存だけ停止。Safety解析は継続 |
| ユーザーが確認済みを押す | acknowledgmentのみ。DANGER/UNKNOWNをSAFEに変えない |
| 有効な修理/母港等の新snapshot | 出撃世代と対象を検証後、再判定して解除可能 |
| 退避候補提示/キャンセル | 対象艦を除外しない |
| goback_port等で退避確定 | 対象出撃/主力/随伴/護衛を検証して確定艦だけ除外 |
| 時間経過/回転/画面遷移/再読み込み | 時間だけで警告解除しない。再取得までUNKNOWN |

ブラウザが何も取得していない事象を、レスポンス内容だけで完全検出はできない。Listenerの健全性（注入状態/bridge/開始・終了・失敗イベント/復帰）とイベント順序を別に監視する。単純な「n秒APIなし」は待機との区別ができないため、それだけでバトル開始と推定しない。観測できない間は判定保証を示さない。

## UI

RootのStack等でPersistent Overlayを置き、艦名とHP/MaxHP、UNKNOWN理由を常時読める位置にする。現行のdialog/Toastは補助として扱う。スクロール・回転・タブ・詳細遷移・フォント拡大・iPad分割表示後も残る。確認操作で小さな固定表示に縮小しても、状態は残す。ゲームの進撃ボタンを自動クリック/強制操作せず、警告表示自体の接触領域は誤操作を避ける。

ダメコン装備を理由に警告を抑制しない。発動/消費/復活HPが未検証ならUNKNOWNと前回大破情報を併記する。演習は別の出撃コンテキストとし、本出撃の安全状態を上書きしない。

SAFEという内部名は便宜的なもの。100%轟沈防止の保証はしない。対応済みfixture・実機で確認した経路のみを対応表に載せる。
